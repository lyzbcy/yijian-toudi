# 投递状态统一刷新（0.5.94）
现状：源码/Skill/Windows本机0.5.94已验收；负责人：本设备维护；最后更新：2026-10-26。未公开。

## 原因和改动
旧“刷新状态”只调用腾讯 inspectApplicationStatus，合并旧 applied，而新投递管理展示 careerApplications；双邮箱页关闭后自动同步也只返回 tab-required。新按钮与 Agent 脚本共用 electron/career-refresh.cjs：按当前账号/简历同步所有已配置邮箱、补接已确认 Agent 回执、只读核对已支持且已打开的官网记录，持久显示覆盖数量/局部列表/登录或读取失败/新增/阶段变化。后台自动同步不弹页；用户主动刷新可重连邮箱页。

## 官网覆盖
当前固定观察规则只有先导 J17815 与上海电气 AI应用开发工程师（27届）；同站多记录、缺页/多页、登录/验证/未知结构均待核对。其他109条不宣称官网刷新成功。官网原文仅保留短状态、无认证参数的地址与观察时间；“已测评”不代表 Agent 做完测试，也不单凭此改为笔试阶段。原始收件/聊天/网申分类不变；刷新不点击申请、测评或撤回，不重投。

## 经Agent核对的邮件关联
POST /v1/career/mail-match 需当前 accountId/profileId、id、mailId、五分钟内 observedAt 与短 evidence。Agent先读正文与申请唯一性，API只校验结构及本机身份，不独立判断内容真假。只绑定该封邮件到该申请，不创建全局模糊公司别名；跨邮箱/身份/已被其他申请绑定拒绝。原邮件公司名保留，复用既有 reconcile 的不回退/终态/日期门禁与待办证据；幂等重复不新增历史。过期/未知邮件不强行推进。

“收到邮件起N天（含当天）”以详情页精确收信时间的北京时间日期为第一天，N天末换算；保存原文短依据和“自然日末换算”，没有精确收信时间或多个冲突期限留待核对。手动日期和已完成待办仍优先。

## 复用脚本
```powershell
node scripts/career-refresh-agent.cjs --confirm-read --reconnect
```
只从本机私有 state 读取 loopback API 地址和令牌，不打印令牌、不读取/导出浏览器 Cookie。无 --reconnect 时不新开邮箱页。POST /v1/career/refresh 与原生按钮共享单飞、显式读取确认与账号/简历切换检查。脚本输出报告不含邮件正文或测评专属链接。
