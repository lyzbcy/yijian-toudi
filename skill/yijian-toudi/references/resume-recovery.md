# 简历与原窗口恢复

仅在填写、官网改版或原任务异常时读取；正常投递不必加载本页。

## 本机事实与官网字段
- 公司专属问题写 `resume.platformAnswers[companyId]`，不把旧全局答案自动归给新公司；只做用户确认的最小patch。UI出现 `_baseUpdatedAt` 冲突时保留草稿，重新读取，别覆盖更新后的档案。
- 校招/实习使用campus，社招使用social；all须先选明确轨道。保持招聘父页、SSO回跳及同一登录会话，iframe仍显示登录时不推断已登录。
- 年月不猜日、至今不填未来日期；动态下拉/日期/只读/内部输入交适用专用控件或人工核对。写入搜索框不等于选中选项。
- 核对附件解析、教育经历数量、公司和当前项目身份。非空人工字段不覆盖；平台显示100%、字段回读均不是官网保存或申请回执。

## 原任务恢复
1. GET `/v1/tasks`、`/v1/diagnostics/workspaces`、`/v1/resume/batch`，区分当前执行与冷启动旧任务。`interrupted`不代表取消、成功、失败或旧窗口仍在；501是环境未提供诊断，不猜替代接口。
2. `node scripts/workspace-status.cjs` 只读原生工作区；usable/reason、登录/验证码状态用于定位，不当完整网页控制或投递成功。remoteDebuggingEnabled也不是普通运行验收。
3. POST `/v1/resume/batch/action` 只用GET返回的原id；running/未知只 `query-widget` 或 `query-saved`。用户完成原页核对后再 `continue`，不重开、不重传、不重放旧批次。
4. `retry-widget` 当前只用于美团已完成任务中的已知失败且目前仍空的控件；非空不改，不重新上传/保存/投递。字节等失败控件先原页核对，不套用美团补齐。
5. `verify-saved` 仅按当前适用美团校招能力，在同会话只读独立页核对新鲜官网数据、DOM与当前档案指纹；已有句柄只query。`lastPersistedVerifiedAt`是核验时间，不是保存时间；改档案、掉线或停止后旧成功不沿用。
6. 项目差异或替换先在APP核对名单、备份及专属确认；字节按当前项目身份与专属nonce继续。未知步骤只查询，不由Skill/API替用户确认删除/重建，教育或全量变更不套用单项目操作。

本机保存、官网保存、申请提交分开报告。以上恢复能力不表示所有公司已适配；以当前运行版本 `/v1/skill` 与实际返回的任务能力为准。
