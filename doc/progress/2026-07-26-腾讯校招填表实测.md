# 腾讯校招简历页填表实测（join.qq.com）

## 背景

腾讯校招与社招是**不同域名**（join.qq.com vs careers.tencent.com），页面技术栈和字段结构完全不同：
- 社招：自研 Vue 组件，选择器用自定义 class（.country-input / .small-select-ul 等）
- 校招：**element-ui**，字段无 name/id，靠 placeholder 定位，有折叠区/动态新增段

社招已有 `fillTencentSocial`，本次为校招新建独立的 `fillTencentCampus`。

## 页面结构实测（2026-07-26）

字段总数 145 个 input + 42 个 textarea。用户（余恩泽）已手填 147 字段，含大量 app 没有的内容：
- **游戏经历** 14 段（原神/崩坏星穹铁道/王者荣耀... 每段含品类+时长+成就+补充说明）
- **获奖信息** 5 项（蓝桥杯/奖学金/优秀员工/优秀干部...）
- **校园项目** 4 个（高校官网重构/知识图谱问答/Unity工具/VR游戏）—— 这些 app 里没有

### 关键交互模式（element-ui）

| 元素类型 | 定位方式 | 填值方式 | 实测结论 |
|---------|---------|---------|---------|
| 文本 input | `input[placeholder="..."]` | `pressSequentially`（逐字符） | ✅ Vue input 事件靠逐字符触发，fill 不认 |
| 日期 (el-date-picker) | `input[placeholder="选择日期"]` | `fill + Enter` | ✅ 支持手动输入日期 |
| 教育「导师/实验室/研究方向」 | `.education_more` 折叠区（display:none） | 先点前一个 `.info_box`「更多」展开 | ✅ 展开后 input 可见可填 |
| 多段实习/项目 | `button:has-text("添加实习经历")` | 点按钮新增段 | ✅ 新段可填 |

### 多段新增的稳定性修复（关键 bug）

**初版用 `locator.last()` 定位新段，5 个项目名全部错位拼接到同一段**（`"个人作品集企微文档检索 P抖音..."`）。

根因：`last()` 在 `pressSequentially` 异步执行过程中，段数变化导致定位漂移。

**修复：段容器标记法**。新增段后立即用 `evaluate` 找到「最后一个空段容器」并打 `data-new-seg="1"` 标记，后续字段全部用 `[data-new-seg="1"] input[placeholder="..."]` 精准定位，填完移除标记。修复后 5 个项目名各归各位。

## 填表策略：app 是 source of truth，有值则覆盖（2026-07-26 与用户确认）

初版策略是「只补缺口不覆盖」，但用户指出这与「一键更新」的语义冲突——用户更新了 app 简历后点一键更新，肯定希望**更新的部分覆盖到页面**。因此策略改为：

1. **app 有值的字段** → 覆盖页面（清空旧值后 pressSequentially 输入 app 值）
2. **值一致** → 跳过（避免无意义重填触发校验）
3. **app 没值的字段** → 不动页面（保护用户在页面手填、但 app 没有的内容，如游戏经历/获奖/校园项目）
4. **实习/项目**：按公司名/项目名匹配——同名段**原地覆盖更新**（打标记后在该段范围内重填），没有的**新增段**

## 安全边界

- **只填不提交**：`fillTencentCampus` 返回 `applyRisk: 'submit-means-apply'`
- 校招页的「提交简历」= **真实投递职位**，比社招更危险
- 软件填完返回，文案强调「请检查后手动保存，切勿点提交」

## 与社招的差异

| 维度 | 社招 (fillTencentSocial) | 校招 (fillTencentCampus) |
|------|------------------------|------------------------|
| 域名 | careers.tencent.com | join.qq.com |
| 技术栈 | 自研 Vue | element-ui |
| 字段定位 | 自定义 class | placeholder |
| 折叠区 | 无 | `.education_more`（导师/实验室/研究方向） |
| 多段 | 「增加工作经验」按钮 | 「添加实习经历/添加项目经历」 |
| 提交风险 | review-before-save（保存非投递） | **submit-means-apply（提交=投递）** |
| 策略 | 全量填 | **只补缺口**（保护用户手填的游戏经历等） |
