# 2026-07-25 · 简历多段经历（v0.3 起点）

## 背景

agent.md 审查时发现「简历只能填一段教育/工作/项目经历」是硬伤（#7），几乎每个求职者都被卡。同时用户决定把简历做成「多段经历（不限段数）+ 多份简历（按求职方向切换 intention+经历）」。本页记录多段经历的落地。

## 已完成

### 数据 schema（electron/seed.cjs）
- 简历拆成 `basic/skills/extras`（全局共享）+ `profiles[]`（按求职方向各存一套 intention/education/experience/projects）
- 每个 profile：`{ id, label, intention, education[], experience[], projects[] }`
- 默认带一个 `default` 简历
- 经历段数不限，由前端按需增删

### 兼容视图（electron/store.cjs）
- `syncResumeActiveView`：每次读写时把 active profile 的 intention/education/experience/projects 镜像到 resume 顶层，旧代码（resume-plan、calculateResumeCompletion、前端）读顶层即可，无需全改
- `applyResumeEdit`：前端 collectResume 只改顶层，必须写回 active profile 才能持久化；这个纯函数解决了「保存后用户输入丢失」的关键 bug，且抽出后可单测
- 迁移逻辑：旧版扁平 schema（顶层 intention/education）自动迁进 default profile，不丢已有经历

### 简历填写计划（electron/resume-plan.cjs）
- 全局字段（basic/intention/skills/extras）路径不变
- 多段经历展开为带段索引的计划条目：`education.0.school`、`education.1.school`...
- 第一段 keywords 保持原文（适配官网第一行），第 N 段 keywords 带「(第N段)」标识，adapter 按官网行号区分
- 每个计划条目带 `segmentNumber/segmentLabel`，便于后续字段差异报告逐段呈现

### 前端（src/index.html + src/app.js）
- HTML 移除写死的 `education.0.*` 等字段，改为 `[data-repeat]` 容器 + 「添加段」按钮
- `renderRepeatableSegments`：按 state 如实渲染（包括空段），不在渲染层清理
- `collectResumeWithoutTrimming`：添加/删除段时用，避免空段被误清
- `collectResume`：保存时清理尾部空段，避免攒一堆空段
- 删除非空段会 confirm，空段直接删
- 段数 ≥6 时出现黄色警告「可能超出招聘网站保存上限，自动填写时会标记为需手动填写」
- `fillResume` 改为「段数变化才重建结构，否则只回填值」，避免用户输入到一半被 innerHTML 重置

## 验证

- 单元测试 32/32 通过（含新增 5 个：多段展开、空段过滤、迁移、applyResumeEdit 写回 profile、不影响其他 profile）
- 静态检查通过（简历结构校验改为「全局字段≥20 + 3 组多段按钮」）
- UI 冒烟 + 多段简历 UI 专项（ui-resume-segments.cjs）：默认 1 段 → 加 5 次到 6 段（有警告）→ 删 1 段 → 填值保存 → active profile 正确写入

## 诚实边界

- 「不限段数」是用户明确选择；视觉模型一度报告「教育段标题缺失」，但 DOM 断言证明三个 section 段标题都在，判定为模型误报（教育 section 紧贴截图裁剪边界）
- 多段经历目前只影响**数据存储和前端编辑**；腾讯简历填写器（tencent-fill.cjs）还按旧的 `education.0` 单段逻辑工作，多段真正写入招聘网站要等 T1.1 字段差异报告（会把段索引映射到官网行号）
