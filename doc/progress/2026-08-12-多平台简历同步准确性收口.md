# 多平台简历同步准确性收口（2026-08-12）

## 结果

- 一键更新统一走 `resume-sync.cjs`，登录、填写和核对复用 `persist:<company>` 内嵌会话。
- 内嵌官网始终保留顶部退出栏；已有工作区时拒绝并发覆盖。
- “全部都要”展开为每家公司社招、校招双轨，每个轨道都有独立暂停/继续游标。
- 腾讯、字节、阿里使用 `inspect → 严格匹配 → 写入 → 延迟回读`；只有回读一致才计入已核验。
- 手机号登录页、验证码、密码、提交、申请、投递等控件禁止写入；认证页会在写前再次检查。
- radio 回读返回被选中的实际答案，“否”不再被误读为“是”。
- 初始 URL、弹窗、导航和重定向都经过平台官网/受信 SSO 白名单。
- 腾讯校招跳转登录页时 Electron 可能返回 `ERR_ABORTED`；只有 WebContents 已落到腾讯白名单内才保留页面，不再误判失败跳过校招。
- BOSS 依平台协议保持本人手动操作；阿里职位在官方子站事实源未验证前保持手动入口。

## 同轮修复

- 备份恢复过去只计算恢复结果但没有写回；现已真正替换并持久化，同时保留本机 Token/邮箱授权。
- 投递成功判定不再把导航栏里的裸“已投递”当当前岗位成功。
- 手动投递结束显示中性未验证提示，岗位继续留在购物车。
- PDF/DOC 附件文案改为“仅本机保存，当前不自动上传”，删除路径限制在应用附件目录。
- Agent 文案与服务端一致：读取的是脱敏简历，官网/邮箱外部动作必须回到应用本人发起。
- 普通“打开官网”改走系统默认浏览器；简历登录与同步只使用内嵌持久会话，避免第二套招聘登录资料目录。

## 使用方式

1. 在设置选择社招、校招或“全部都要”。
2. 在本机简历填写并保存一次。
3. 点“一键更新”；每到一个官网，先处理登录/验证码，再核对已写字段。
4. 用顶部“完成”结束当前站，再点“一键更新”继续下一站；取消会保留当前目标供重试。
5. 软件不会替用户点击保存、提交申请或投递按钮。
