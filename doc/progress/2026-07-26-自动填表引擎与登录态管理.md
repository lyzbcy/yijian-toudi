# 自动填表引擎与登录态管理（2026-07-26）

> 本文记录项目第一次引入 **playwright 浏览器自动化** + **持久化登录态管理** 的设计与实测。这是兑现 agent.md「一键更新所有公司简历」初心的关键基础设施——之前 App 内嵌浏览器的 `workspace.run` 只能跑 JS，处理不了招聘站的 Vue/ant-design 自定义组件（学历下拉、日期选择器），导致「填表填不进去」。

## 背景与问题

### 之前的局限
- App 用 Electron `WebContentsView` 内嵌浏览器，通过 `workspace.run(JS)` 操作页面
- 实测腾讯社招：只能填标准 input/textarea，**学历（div 弹层）、日期（自定义日历）完全填不了**
- `workspace.run` 没有点击、等待、截图能力，处理不了现代 SPA 框架的自定义组件

### 用户需求（2026-07-26）
1. 探索各家是否支持账号密码登录（支持则 App 里保存账密自动登录）
2. 不支持账密的，用 playwright 打开浏览器让用户登录一次，保存登录态
3. 一键投递前检查每家登录态，过期的提示用户重新登录
4. 实测跑通才能交付

## 关键事实探索（实锤）

| 公司 | 校招登录方式 | 支持账密？ |
|------|------------|-----------|
| 腾讯 | 微信/QQ 扫码 | ❌ |
| 字节 | 手机号 + 短信验证码 | ❌ |
| 小米 | 手机号 + 短信验证码 | ❌ |
| 京东 | 扫码 | ❌ |
| 美团 | 手机号 + 短信验证码 | ❌ |

**结论**：6 家校招**全部不支持账号密码登录**（中国互联网招聘站普遍用扫码/短信验证码做风控）。因此「App 保存账密自动登录」方案不适用，采用**持久化登录态**方案。

### 持久化登录态方案
- 每家公司一个 `userDataDir`：`~/.yijian-toudi-autofill/<companyId>`
- 用户首次扫码登录 → playwright 保存 cookie/LocalStorage/IndexedDB 到该目录
- 后续自动复用登录态，跨进程持久化
- 登录态过期 → `checkLogin` 检测到 → 提示用户重新登录

## 实现：auto-fill-engine.cjs

新增 `electron/auto-fill-engine.cjs`，playwright 驱动的浏览器控制引擎：

### 核心能力
- `launchContext(companyId, {headless})` —— 启动持久化浏览器（复用登录态）
- `checkLogin(companyId, recruitType)` —— 检测登录态是否有效
- `openForLogin(companyId, recruitType)` —— 打开可见浏览器让用户扫码登录
- 用 `executablePath` 硬编码 chromium-1223 路径，绕过 playwright-core 1.61 要 1228 的版本检查

### checkLogin 判定逻辑（经多轮实测修正）
综合 3 个信号判定登录态：
1. **URL 跳转**：跳到 login/passport 页 = 未登录（强信号）
2. **登录入口可见**：页面文本前 200 字有独立「登录」二字 = 未登录（京东等 SPA 不跳转但有登录链接）
3. **页面内容**：textLen < 50（页面加载失败/空壳）= 不确定，保守判未登录

### COMPANY_URLS 配置
6 家公司的校招/社招简历页与登录页 URL，按 recruitType 分流。

## Agent API 集成

新增两个命令（`electron/main.cjs` + `electron/agent-server.cjs`）：
- `{"action":"login_status","companyId":"tencent","recruitType":"campus"}` —— 检查登录态
- `{"action":"open_login","companyId":"tencent","recruitType":"campus"}` —— 打开浏览器登录

## 实测结果（2026-07-26）

### login_status 批量检查（6 家）
```
【tencent】❌未登录 | textLen=87 loginEntry=true
【bytedance】❌未登录 | textLen=178 loginEntry=true
【xiaomi】❌未登录 | textLen=56 loginEntry=true
【jd】❌未登录 | textLen=315 loginEntry=true

【baidu】❌未登录 | textLen=0 loginEntry=false
```
6 家全部正确判为未登录（待用户扫码）。

### 发现的关键 bug（已修）
1. **多进程冲突**：多次重启 App 会有多个 Electron 主进程抢端口，导致 API 由旧进程响应、新代码不生效。解决：启动前按 PID 杀光所有 electron 主进程。
2. **checkLogin 误判**：京东 SPA 未登录也不跳 login 页（展示空表单骨架），仅靠 URL 判定会误判为已登录。解决：加「登录入口可见」+「页面内容长度」信号。
