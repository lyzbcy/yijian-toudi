# 六厂通用简历引擎接入与真站实测（2026-08-18）

## 目标

兑现 agent.md 核心承诺：所有支持的公司都能「一键更新简历」。今天把小米/京东/美团/百度从「打开官网手动填」（manual）升级为与字节/阿里相同的通用自动填写引擎，并逐家真站实测校准。

## 代码变更

1. **小米/京东/美团/百度升级为通用引擎**（`adapters/registry.cjs`）：`fillResume` 全部接入 `generic-resume-fill.cjs`（inspect → 严格匹配 → 写入 → 延迟回读），capabilities.resume 从 manual 升到 degraded；`seed.cjs` 能力矩阵同步。
2. **真站 URL 校准**（`platform-manifests.cjs`，全部实测确认）：
   - 小米社招简历页：旧 `/user/profile/resume` 已 404，真实编辑页是 `/index/resume/edit`（未登录跳 `/index/login`）；社招登录页从 campus 改为 `/index/login`。
   - 美团社招简历页：旧 `/web/personal/resume` 已 404，真实编辑页是 `/web/personal-center/resume-detail?type=social&mode=edit`。
   - 阿里受信登录域新增 `mozi-login.alibaba-inc.com`：社招简历页 302 跳该域 SSO，此前被白名单拦截报 `ERR_FAILED`，现可正常打开登录页。
3. **登录页识别修复**（`form-inspection.cjs`）：
   - `login.html`/`login.aspx` 等带扩展名路由此前不被 authRoute 识别（token 是 `login.html` 而非 `login`），腾讯校招登录页曾被误判为表单页；现去除扩展名再比对，并补充 `sso` 路由。
   - 百度未登录时返回 JSON `{"status":"need-login"}`，既无表单也无登录控件，现按登录态识别。
   - 探测加 1.2s 稳定窗口：SPA 跳转登录页的竞态期间，不再因首帧残留输入框立即返回「有表单」。
4. **挂死修复（产品级 bug）**（`login-manager.cjs`）：页面在 `executeJavaScript` 执行期间跳转会让 Promise 永远不 settle，一键更新会永久卡在该站。`run()` 现加 15s 超时兜底；两个 fill 适配器的探测在超时后等 2s 重试一次。
5. **空表单防误报**：探测到输入框但过滤后无可用字段（登录页常见）时，返回 login-required/manual-required，不再返回「0 写入/114 手动」的 review-required。

## 开源整合说明

各大厂简历页结构差异大且反爬频繁，没有可直接复用的「某厂一键更新简历」开源实现；本项目沿用成熟开源项目的思路本地重写（Folio 的分级匹配/safe threshold/never submit、CareerPulse 的 adapter registry/confidence、JSON Resume 的交换格式、Playwright 的采集，见 `doc/plans/2026-08-12-多平台简历同步与职位聚合设计.md`）。致谢在 README 与设计文档中维护。

## 剩余边界

- 除腾讯（已完成一次真实写入核验）外，其余六家的「真实保存→回读」验收仍需用户登录各平台账号后完成；未登录前引擎正确停在 login-required，不猜选择器。
- 校招「提交简历」=真实投递，软件只填不提交的边界保持不变。
