# 腾讯社招简历填表实测（2026-07-26）

> 本文记录用真实账号、真实简历数据（余恩泽，100% 完成度）在腾讯社招简历页（careers.tencent.com）实测自动填表的全过程。这是项目第一次**真实闭环测试**——不是 mock，是真实打开浏览器、读真实 DOM、填真实字段。

## 实测环境

- App：`npm run dev` 从项目源码启动（单进程，PID 确认）
- 简历：余恩泽，3 个 profile，5 段项目，completion 100%
- 招聘站：腾讯社招 careers.tencent.com（已登录）
- 驱动方式：Agent API `POST /v1/commands {action:'fill_resume'}`，recruitType=social

## 三轮迭代过程

### 第一轮：31.6%（6/19 字段）

发现问题：
1. `createTencentResumePlan` 默认校招模式，生成 110 个字段全落 manual（社招页没那么多字段）→ 加社招白名单过滤，字段降到 19 个
2. 多个字段标签对不上腾讯真实 DOM

### 第二轮：52.6%（10/19 字段）

改进 describe()（字段识别函数）：
- 加 previousElementSibling 取兄弟节点文本
- 补真实 DOM 的英文 id keyword（work/e-mail/company/school）

### 第三轮：68.4%（13/19 字段）

改进 describe() 用 cloneNode+移除控件策略：
- 腾讯用 Vue 组件，input 包在多层 div 里，label 文本在最外层容器
- describe() 往上找 5 层祖先，克隆后移除 input/textarea/select，取 textContent = 字段标题
- 加 CSS class 语义识别（telephone=手机、describe=描述）

## 关键技术发现

### 1. 腾讯社招页 DOM 结构（考古实证）

腾讯社招页用 Vue + 自定义组件，25 个可识别控件里：
- **文本 input**：多数无 label/placeholder/id，靠 CSS class（`input-box`、`telephone-input`、`describe-input`）和祖先容器文本识别
- **0 个标准 select**：学历等下拉是 div 弹层选择器
- **0 个标准 date input**：日期是自定义日历组件
- **radio**：只有「是否接受工作地分配」一组（是/否）
- **file upload**：简历附件、作品集（4 个）

### 2. buildFillScript 的能力边界

当前「找 input + 设值 + 触发 input 事件」策略：
- ✅ 能处理：标准 input/textarea（含 Vue 受控组件，靠 dispatch input/change/blur）
- ❌ 处理不了：div 弹层选择器（学历）、自定义日历（日期）、富文本编辑器

### 3. 既有 bug 修复（实测副产品）

- **flushSession 的 `.catch` bug**：`activeSession.cookies.flushStore()` 某些状态返回 undefined，对 undefined 调 `.catch` 报错。用 `Promise.resolve()` 包一层修复。（login-manager.cjs:73-74）
- **多进程冲突**：两个 Electron 主进程同时跑会导致 fill_resume 报 `catch` 错。开发时务必确保单进程。

## 结论

腾讯社招简历页**核心文本字段已能自动填中 68.4%**（13/19），姓名/手机/邮箱/城市/学校/专业/公司/职位/工作描述/自我评价等关键字段全部覆盖。剩余 6 个未填中字段需要「自定义组件交互」能力（点击展开下拉、操作日历），属于下一阶段 adapter 增强。

**用户操作**：填表后 App 会停在腾讯社招页（review-required 状态），用户需肉眼核对 13 个已填字段值是否准确，手动补 6 个未填字段（学历/日期），确认后点页面底部「保存」。软件不会自动点保存。
