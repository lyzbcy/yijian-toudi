# 微信快捷登录：人机协作方案

## 背景

用户余恩泽反馈：腾讯校招登录页支持微信登录，且桌面微信已登录时，可以走「快捷登录」省去扫码。流程实测如下（2026-07-27）：

1. 打开 `join.qq.com` 登录页，勾选隐私协议
2. 点「微信账号登录」(`.item.item_wechat`)
3. 等 3-5 秒，跳到 `open.weixin.qq.com`，出现快捷登录按钮（带微信头像+昵称）
4. 点「微信快捷登录」按钮 (`.js_quick_login_btn`)
5. **微信桌面端弹出强制置顶的授权确认窗口**：「腾讯HR统一登录 申请使用 你的昵称、头像 [拒绝] [允许]」
6. 用户点「允许」→ 浏览器显示「登陆中」→ 2 秒后登录成功

软件能自动完成 1-4 步（省去扫码），但第 5 步的「允许」按钮**无法可靠自动点击**。

## 为什么不自动点「允许」

微信授权弹窗是微信 App 内部的**跨进程自绘 UI**，不是标准系统控件。尝试过的自动化方案全部失败：

| 方案 | 结果 | 原因 |
|------|------|------|
| AppleScript Accessibility `click button "允许"` | ❌ 找不到按钮 | 自绘 UI 不暴露给 Accessibility API |
| AppleScript 键盘 Tab + Enter | ❌ 焦点不在按钮 | 窗口不响应标准键盘焦点 |
| JXA `CGWindowListCopyWindowInfo` 取窗口坐标 | ❌ 返回空 `[]` | 需屏幕录制权限，且坐标点击仍不可靠 |
| 截图 + 视觉模型定位 + 坐标点击 | ❌ 不可靠 | 依赖系统权限、视觉模型解析、坐标精度，任一环节失败即卡住 |

**根本问题**：这是登录场景，用户本就在场。把一个「跨进程、自绘 UI、需系统权限、且依赖外部模型」的点击塞进自动流程，可靠性远低于让用户自己点。点一下是 2 秒的动作。

## 采纳的方案：人机协作

软件自动完成到第 4 步（点快捷登录按钮，省去扫码），第 5 步的「允许」**留给用户点**。具体：

- **后端 `loginWithWechat`** (`electron/auto-fill-engine.cjs`)
  - 点完 `.js_quick_login_btn` 后，置 `needUserConfirmAllow = true`
  - 等待超时从 30s 加长到 60s，给用户充足时间点「允许」
  - 用页面内容（出现「你好/我的简历」）而非 URL 判断登录成功
- **IPC handler** (`electron/main.cjs`)
  - `needUserConfirmAllow` 透传给前端
  - task detail 实时更新为「请在弹出的微信窗口点「允许」完成授权…」
- **前端** (`src/app.js`)
  - 收到 `needUserConfirmAllow` 时弹 toast 提示：「微信桌面端会弹出授权窗口，请点「允许」完成登录」
- **设置开关** (`src/index.html` 设置页「登录辅助」卡片)
  - 「桌面微信已打开，优先微信快捷登录」checkbox
  - 文案明确写清：「点完「快捷登录」后，微信会弹窗让你确认，**你点一下弹窗里的「允许」**即完成登录」

## 适用范围

- ✅ 腾讯（`join.qq.com` / `careers.tencent.com` 共用微信开放平台 appid）
- ❌ 字节/小米等：用手机号登录，不适用微信快捷登录
- 前提：用户电脑的**个人桌面微信**已登录（非企业微信）
