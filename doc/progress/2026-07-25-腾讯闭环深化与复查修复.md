### #17 腾讯字段差异报告（design §4.2）

把腾讯简历填写从「模糊关键词填表」升级成三步可复核流程：

1. **inspectTencentResume**（tencent-fill.cjs）：打开腾讯简历页，读出所有可识别表单控件（label/类型/当前值/选项），只读不写。新增 `INSPECT_FORM_FIELDS` 页面脚本。
2. **planTencentResumePatch**（tencent-fill.cjs，纯函数）：对比本地简历值和 inspect 读到的远端字段，生成四元组差异清单：
   - `action: fill`（本地有值、远端空或不同，且匹配到字段）
   - `action: skip`（本地与远端一致）
   - `action: manual`（找不到匹配字段，或 select 选项不含本地值）
   - 每条带 `localValue/remoteValue/risk/matchedField/segmentLabel`
3. **fillTencentResume**：保持原填写逻辑，填写后再读一次远端字段生成 patchPlan，随结果返回。

前端：填写完成后若有 patchPlan，弹 `#resumeReportDialog` 展示差异表（本地字段/本地值/腾讯当前值/动作/匹配与风险），明确标注「软件没有点击保存」。

## 2026-07-25 · 内嵌投递安全退出修复

### 用户现场问题

点击「一键投递」后，失效的腾讯岗位会打开 404 页面；腾讯网页占满主窗口，应用的退出按钮不可见。点击腾讯页面里的「返回首页」只会留在腾讯站内，无法回到「一键投递」。

### 根因

1. `WebContentsView` 使用窗口外框尺寸计算边界，原生网页可能覆盖预留控制区。
2. 控制栏虽然被改到顶部，但 DOM 仍放在进入工作区后会被 `display:none` 的 `.main` 容器内，导致它与主界面一起消失。
3. 腾讯 404、适配器异常和部分失败状态没有统一销毁原生网页层。
4. 启动时等待远端更新检查完成后才绑定按钮事件；网络慢时界面已经出现，但按钮暂时不可用。

### 修复

- 顶部固定保留 52px 控制栏，并把控制栏移到 `.main` 外；按钮明确显示「取消并返回」。
- 原生网页改用 `getContentSize()` 计算范围，只能从 `y=52` 开始。
- 窗口缩放、最大化、还原和进出全屏时重新计算范围。
- 新增幂等 `closeWorkspaceIfOpen()`；腾讯 404、脚本异常以及不可接管的失败状态全部兜底关闭。
- 腾讯 API 返回的可信 `http` 岗位链接统一升级为 `https`。
- 更新检查改为后台执行，不阻塞界面事件绑定。
- UI 测试现在尊重 `--user-data-dir` 临时目录，不再读取或修改用户真实简历数据。

### 验证

- 单元测试：82/82 通过。
- 项目静态检查：通过。
- 桌面 UI 冒烟：通过。
- 内嵌退出专项 Electron 测试：顶部栏 `y=0`、高度 `52px`；点击「取消并返回」后主界面恢复且工作区关闭。
- 截图：`test-output/workspace-top-bar.png`。

### 行为边界

- 岗位 404、加载失败或脚本异常：自动回到购物车，岗位保留并显示失败原因。
- 需要登录、验证码、人工检查或最终确认：保留内嵌页面，但顶部退出栏始终可见。
