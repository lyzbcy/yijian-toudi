## 引擎升级：同页序号定位

美团（mtd）/腾讯校招（el）组件的输入框没有 id/name，旧规则全部转人工。新增第三种定位方式：高置信 label 匹配 + 同页同序号（inspect 与写入同页面状态，复刻 INSPECT_FORM_FIELDS 的控件筛选保证序号对齐），写入后仍有延迟回读核验兜底。腾讯校招因此从 0 → 5 个核验字段。

## 未决（转未决问题.md）

字节/小米校招简历页表单不渲染，需要下季校招开放或人工在页面内探索真实入口后校准。

## 补充（2026-08-24）：简历附件自动上传

- `login-manager.setInputFiles`：页内 `DataTransfer` 构造 File 直接赋给 `input.files`（Chromium 合法途径，与真人选文件等价），免疫 React/Vue 重渲染。
- 通用引擎与腾讯适配器新增 attachment 步骤：用户在软件里上传过 PDF/DOC 且官网有简历附件入口时自动注入；antd 组件消化文件后重置 input 属正常行为，以「赋值瞬间成功」为判据。
- 京东校招真站 E2E 验证：3 字段写入核验 + 附件 resume-*.pdf 上传成功（`attachment.uploaded: true`）。
- CDP `DOM.setFileInputFiles` 在 React 站点因节点被重渲染替换而失效；Electron 43 已移除 `setFileChooserInterceptor`，DataTransfer 是唯一稳定方案。

## 腾讯专项攻坚（2026-08-24 晚）：5 → 21 字段全部核验

三项根因修复（全部真站验证）：
1. **匹配升级**（field-matching）：中文「请输入X/请填写您的X」前缀剥离后强匹配；≥4 字长关键词包含按次强信号；radio 控件值+关键词双确认；file input 不参与文本匹配；basic.city 排除面试城市。
2. **element-ui 写入状态机**：合成 input 事件缺 focus/compositionstart/compositionend 会被组件丢弃，随后表单刷新把字段回滚为空。补全事件序列后 8 个"被写空"字段全部稳定。
3. **多轮补写**：批量写入触发表单段重挂载（字段短暂消失），带 3 轮重试 + 1s 稳定窗。

结果：腾讯校招 21/21 高置信字段全部真实写入并回读核验，0 失败，附件上传成功；京东 3→5（其页面多为自定义选择器，天花板有限）。91 个 manual 中约 70 个是腾讯页面不存在的字段（生日/籍贯/民族等），属正常。
