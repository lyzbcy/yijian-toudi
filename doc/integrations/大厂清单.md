## 适配进度登记

每完成一个站点的真实适配，在这里登记。**只有走过实测的站点才能从"待适配"改为"已适配"**，否则违反 doc/README.md 的诚实纪律。

### 腾讯（社招岗位抓取）—— 2026-07-23 实测通过

- **适配范围**：社招岗位列表抓取（不含投递、不含校招）。
- **技术路径**：直接调公开 JSON API，不走浏览器自动化。
  - 列表：`GET https://careers.tencent.com/tencentcareer/api/post/Query`
  - 参数：`timestamp` / `pageIndex`（从 1 起）/ `pageSize` / `language=zh-cn` / `area=cn`
  - 详情（按需）：`GET .../api/post/ByPostId?postId={PostId}`
- **登录要求**：岗位列表不登录可读全量（实测约 2295 个）；投递必然需要登录。
- **字段映射**（`electron/adapters/tencent.cjs`）：
  - `RecruitPostName`→title、`BGName`→department、`LocationName`→city、`CategoryName`→tags、`RequireWorkYearsName`→experience、`Responsibility`→summary、`LastUpdateTime`→postedAt、`PostURL`→url
- **已知坑**：
  1. 部门字段是 `BGName`，不是老教程里的 `DepartmentName`；
  2. 列表接口不含学历，学历在详情接口的 `Requirement` 里，列表抓取先标"待进详情"；
  3. 用缓存的旧 `postId` 调详情可能 500，详情调用必须用列表里拿到的最新 `PostId`；
  4. 校招是另一套体系（`join.qq.com`），API 不通用，需单独适配。
- **实测结果**：近 30 天抓到 1571 个真实岗位，字段映射正确，日期过滤生效，16.6s 完成。
- **待办**：投递适配（需浏览器登录态）、学历字段补全（进详情）、校招适配。

### 百度（社招岗位抓取）—— 2026-07-24 实测通过

- **适配范围**：社招岗位列表抓取（不含投递）。
- **技术路径**：解析 SSR 页面内嵌数据（岗位直接嵌在首屏 HTML）。
  - 入口：`GET https://talent.baidu.com/jobs/social-list?search={关键词}`
  - 数据位置：`window.__INITIAL_DATA__.listData.listDetailData`（每次约 10 条）
  - 全量覆盖：用多个关键词分批请求（java/前端/python/算法 等）
- **登录要求**：不需要。SSR 直接吐数据。
- **字段映射**（`electron/adapters/baidu.cjs`）：
  - `name`→title、`bgShortName`→department、`workPlace`→city、`postType`→tags、`updateDate`→postedAt、`workContent`→summary（首屏即带全文，比腾讯还全）
- **已知坑**：
  1. `__INITIAL_DATA__` 是 JS 字面量含 `undefined`，需替换成 null 再 JSON.parse；
  2. 赋值后紧跟其他 script，要用括号深度配平提取完整 JSON，不能用行尾做边界；
  3. `education`/`workYears` 常为空，兜底为"详见要求"。
- **实测结果**：5 个关键词抓到 50 个真实岗位，含任职要求全文，3.3s 完成。

### 字节跳动（社招岗位抓取）—— 2026-07-24 实测通过

- **适配范围**：社招岗位列表抓取（不含投递）。
- **技术路径**：CSRF token 两步法（React SPA，数据走 XHR）。
  - 第一步：`POST https://jobs.bytedance.com/api/v1/csrf/token`，body `{portal_entrance:1}`，拿 `atsx-csrf-token` cookie
  - 第二步：`POST https://jobs.bytedance.com/api/v1/search/job/posts`，body `{keyword:"",limit,offset}`，带 token cookie + Referer
- **登录要求**：不需要（CSRF token 是匿名会话令牌，非账号）。
- **字段映射**（`electron/adapters/bytedance.cjs`）：
  - `title`→title、`code`→department、`city_info.name`→city、`job_category.name`→tags、`publish_time`(毫秒)→postedAt、`description`→summary
- **已知坑**：
  1. token 与会话绑定，几分钟到几十分钟失效（失效返回 **405** 而非 401），必须"取 token→立即查岗位"同会话完成；
  2. Referer 和完整 Chrome UA 强制校验，缺失会 405 或空响应；
  3. `city` 参数实测无效，城市筛选需拿到结果后本地过滤；
  4. `keyword=""` 返回全量（封顶 10000）。
- **实测结果**：近 60 天抓到 22 个真实岗位，含飞书/TikTok 等业务线，token 失效自动重试生效，2.9s 完成。

## 字段说明

- **登录方式**：账号密码 / 微信扫码 / 企业 SSO / 验证码 等。适配时确认并填入，关系到登录态保留策略。
- **适配状态**：`❌ 待适配` → `🚧 开发中` → `✅ 已适配（YYYY-MM-DD 实测）` → `⚠️ 需要维护（站点改版）`。
- **最后实测**：最后一次跑通抓取/填表/投递链路的日期。超过 30 天未实测的站点应重新验证。
