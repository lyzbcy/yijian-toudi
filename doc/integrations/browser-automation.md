# 浏览器自动化与验证码策略

> v0.5.10 调试优先使用同一 Electron 会话的网页级 DOM/CDP 入口，支持 Shadow DOM、跨域 iframe 与登录子窗口，见 [AI 网页调试](ai-browser.md)。Kimi WebBridge 仍用于外部浏览器；桌面坐标仅用于网页工具之外的原生交互。

> 2026-09-29 更新：v0.5.4 APP 主入口已改为批量选择与 4/6 独立窗口，详见 `doc/integrations/resume-batch.md`。本文的逐站单窗口描述仍适用于兼容 API；保存与投递核验边界不变。

## 目标

应用通过本地桥接层打开内嵌招聘工作区，浏览器在本机完成导航、读取与高置信填写，登录态不上传。顶部退出栏始终保留，登录与填表使用同一个 `persist:<company>` 会话。

当前实现已包含统一多平台编排、腾讯/字节/阿里高置信填写与回读，以及其他平台官方页人工接管。普通“浏览官网”走系统默认浏览器，不再创建第二套招聘登录资料目录。

## 适配器契约

每家公司单独维护：

1. `detectLogin(page)`：判断是否需要登录。
2. `listJobs(page, filters)`：分页读取岗位。
3. `normalizeJob(raw)`：清洗成统一字段。
4. `readProfile(page)`：读取平台已有简历。
5. `diffProfile(local, remote)`：只生成差异。
6. `fillProfile(page, patch)`：填表、延迟回读，但不自动保存或提交。
7. `prepareApplication(page, job)`：只打开详情页，由用户本人决定是否提交。

## 验证码经验

参考“知识库 AI 开发第二期”的 2026-06-17 结论：

- 旧项目曾因 `HeadlessChrome` UA 被腾讯风控判为环境异常；修复浏览器环境后链路才通过。
- 缓存或复用旧浏览器会话前必须校验会话状态，不能默认安全复用。
- 纯视觉识别对不同拼图并不稳定，不应成为通用承诺。

本项目采用更保守的产品策略：

- 默认用真实有界面的内嵌工作区；
- 登录、验证码和异常风控页面出现时暂停并提示用户接管；
- 不在未获得站点授权与稳定证据前内置“绕过风控”的行为；
- 每个适配器都要记录最后实测日期，网站改版后自动降级为“需要维护”。

## Token 节约

招聘站点稳定后，优先使用经过回归测试的固定选择器与清洗脚本；只有结构检测失败时才把页面摘要交给 Agent 分析。这样将日常全量更新的模型消耗降到最低。

## 阿里校招分区（v0.5.51）

真实官网FormCard按个人信息、教育情况、实习/项目经历、其他信息定位，编辑/保存可能是div[role=button]。51只点精确编辑/添加，不点击保存。四分区可同时编辑，结束后按卡片和字段描述重新定位回读。项目表格以“添加更多项目经历”界定；含.name仍是项目，tfitem非连续。多段新增最多20次、不删多余行。公司/组织名称与本地项目名、服务客户不同，保留人工核对；项目事实带标签合并到描述，并公开报告合并表示。组合框搜索输入与只读日期不视为普通文本；未验证控件不写入，工作组未出现时不改写项目行。真实SDK证据为隔离封锁网络后的草稿核对，不是官网保存。

## 京东校招学校（v0.5.52）

按edu分组、学校名称行和唯一搜索框输入全称，使用官网只读候选接口；仅从当前combobox的aria-controls菜单选唯一完整匹配。空菜单时不搜索其它全局列表。失败恢复原查询，Escape发送搜索输入并等自身aria-expanded关闭，不动预先打开的其它菜单。每字段独立脚本，所有文本结束后按结构最终回读widget；已重置字段计不一致。日期仍保留真实精度，月份和至今不伪造具体日。隔离验收允许唯一GET学校查询，其它写入封锁。

## 隔离真实SDK验收可见性（v0.5.52）

字节/小米认证正常、正确简历路由在隐藏Window中仍可能停止初始化。52同WebContents只改showInactive，两站0控件变46/32且loading=false，未手动dispatch或改存储。隔离真实SDK应保留只读网络直到表单初始化完成，以showInactive避免抢用户焦点，结束恢复原可见性。不得把hidden实验0字段记登录失败、猜改路由；不得改官网保护。填写阶段继续封锁外部写入并记录保存/提交点击0。原个人百度及未保存草稿保持打开。

## 53腾讯校招结构填写与开发语言（2026-10-05，开发候选）

生产适配器校招分支按直接分区标题、经历组和行标题定位，控件数量/类型/占位符不符时保留人工项。手机号选择唯一可写文本，保留国家代码。实习栏仅接受明确实习来源，不把全职改为实习；按精确添加按钮补组、最多20组，不删除原组。项目名与角色分开，背景/贡献/技术/成果/链接带事实标签合并至描述，并报告sourceKeys，不把合并表示当独立官网字段。学校、学历、日期及其他选择控件继续人工。

开发语言按分隔符拆分、去重，只选所属多选菜单唯一完整匹配；操作前预检全部增删候选，缺失/重复/禁用则不改。ElementUI弹层打开后移至body，使用打开前确认的自身子菜单绑定，不猜全局弹层；失败回滚旧选择并关闭自己的菜单，不动其他已开菜单。语言操作完成后再次回读全部文本，后续渲染重置不计成功。

最终回读仍只证明草稿，用户本人确认保存后才核对官网持久结果。

## 54腾讯校招学校/学历/日期与状态广播修复（2026-10-05，未正式发布）

学校只操作对应教育组SchoolSearch原生输入，核对DOM与外层value模型；其inputValue watcher将输入传给父模型，证明native-school-text，不证明目录验证。学历只使用本人已给事实和明确别名（硕士→硕士研究生、博士→博士研究生、专科→大专），要求所属菜单唯一完整可用选项，缺失/重复/禁用保留原值，关闭自身菜单并等待动画。

日期仅接受真实合法YYYY-MM-DD和正序范围，不把月份或至今编成具体日。ElDatePicker和内部ElInput共享根，需核对外层picker模型；隐藏/未聚焦窗口原生focus可不触发focus事件，若自身picker未初始化，只向这个输入补发focus事件，等待所属picker再输入，Escape关闭，失败恢复原DOM/模型。合成精确日实站隔离SDK输入后模型相等且原值已恢复，不把合成日期当本人事实。

真实隔离SDK29控件最终一致、35来源事实人工、0不一致/0失败，26文本DOM、24个可检查文本模型、学校/学历模型相等；132无关控件保留，14个精度不足日期人工，本次未补组，0保存/提交点击。首次学校被学历动画阻挡及三次日期模型失败保留。24项Chromium边界回归通过，不代替官网保存。证据tencent-staged-sdk-v54.json、tencent-native-date-synthetic-v54.json及其attempt记录。
