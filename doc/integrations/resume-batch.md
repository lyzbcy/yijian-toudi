# 批量简历更新
现状：v0.5.4 开发候选，Windows 隔离回归通过；官网保存仍待逐站验收。
负责人：项目维护者。
最后更新：2026-09-29。

## 使用
APP「简历 → 批量更新简历」先保存当前本地编辑，再弹选择面板。支持全选、部分选择、记住上轮目标；空选择禁止开始。目标来自适配器能力矩阵，与设置的招聘方向一致；“全部都要”分为社招和校招。

4 窗口按 2×2 平铺，6 窗口按 2×3 平铺到主窗口所在显示器。每个平台有独立原生窗口和 WebContentsView，可最大化；Alt+Tab 回主窗口查看进度、重试、停止。窗口间留空隙以兼容 Windows DPI 舍入。窗口属于本机 APP，不走浏览器桥。

登录、验证码、人工核对只暂停该平台。窗口保留，占一个并行槽；关闭后下一平台补位。同一公司的社招/校招共用既有 `persist:<company>` 会话，因此同公司方向强制串行，其他公司继续执行。不会因一个登录页覆盖另一个页面。

## 记录与真实性
- `resumeSyncHistory[targetId].lastAttemptAt`：实际开始尝试时间，不是更新时间。
- `lastUserConfirmedAt`：用户明确点击「我已在官网保存」后记录；显示“用户确认，未自动验收”。登录中/填写中不能确认。
- `lastUpdatedAt`：仅适配器返回 `saved` 且有非空 `saveEvidence` 才记录。当前真实站适配器尚无这一保存闭环，不凭字段回读写入此时间。
- 关窗、停止、填写、字段回读均不产生保存时间。重复更新不抹掉历史确认时间。
- 指纹对比当前实际简历内容，忽略 `updatedAt`、completion、非激活模板。保存时指纹单独保留，避免新尝试覆盖旧保存记录后误报“内容一致”。
- 历史与选择写入 JsonStore；重启不自动续跑，将未完成 running/queued 标为 interrupted。

## 实现边界
`resume-batch.cjs` 管理选择校验、并行槽、同站互斥、取消、历史；`resume-batch-window.cjs` 管理平铺窗口；`login-manager.cjs#createLoginManager` 创建独立工作区，原导出仍是兼容单例。主窗口的旧串行登录/填写入口与新批次互斥。

停止先置取消标记，关闭各视图；在途适配器实际结束前保留锁，迟到结果不计成功。重试只针对当前平台，不重跑所有目标。一次平台错误不自动刷新重试。真正的网站登录、协议确认与提交仍遵守适配器已有行为。

## 验证
`node --test test/resume-batch.test.cjs` 验证选择、并发上限、同站串行、取消锁、迟到回执、三种时间、磁盘失败和窗口几何。

`node test/ui-resume-batch.cjs` 在隔离 Windows Electron 中拦截 HTTPS 为本地样本：真实 IPC、原生窗口、独立 Session、通用填写和回读、队列补位、全选/半选、停止、历史重启读回。旧 UI sync-all/sync-cancel 测试入口转到本测试；串行编排单测保留。

`node test/live-resume-batch.cjs` 是显式执行的官网烟测，不加入默认后台测试。使用无登录态、空简历的独立目录，真实访问四家官网，不访问 Boss、不点击保存/申请。结果不能当作用户账号简历更新成功。
