# 开发经验与可复用方案

## 诚实状态比漂亮数字重要

聚合招聘数据最容易出现的产品风险，是把 seed、缓存或失败后的旧数据显示成“刚刚抓取”。统一字段必须保留 `source`、`fetchedAt`、`adapterVersion` 和 `health`。MVP 用“演示数据”显式标记，刷新不会伪造新增岗位。

## 浏览器会话不能无条件复用

旧项目验证过：残留会话可能携带错误 UA、过期登录或异常页面。会话复用前至少检查当前 URL、登录状态、浏览器环境与适配器版本。失败时关闭并重新进入受控流程。

## 自动化的用户接管要做成一等状态

不要把验证码当作异常弹窗临时处理。任务状态应明确包含 `waiting_for_login`、`waiting_for_captcha`、`waiting_for_confirmation`，UI 要告诉用户当前页面、需要做什么和完成后如何继续。

## 静态页面缓存

GitHub Pages 的介绍页同时维护内联 `PAGE_V` 和 `version.json`。发布页面修改时两者必须同步递增，防止用户长期看到 CDN 旧缓存。
