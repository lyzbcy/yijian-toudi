# 一键投递候选体验与录制准备

适用候选：v0.5.39 Windows x64。此文供维护者验收/录制准备，当前还未正式发布，不应标为完整交付。macOS 需单独完成验收。

## 安装和第一次使用

1. 从作者正式 GitHub Release 取得对应平台安装包与 SHA-256 文件，不使用来历不明的转载包。当前候选在本机 `release/yijian-toudi-setup-0.5.39.exe`，正式下载地址尚未发布。
2. Windows 可用 `Get-FileHash -Algorithm SHA256 -LiteralPath '<安装包路径>'` 比对校验文件。候选未完成签名发行验收，Windows 的信任提示和签名状态必须在实际分发说明中如实披露。
3. 启动安装向导，选择安装目录与是否创建桌面快捷方式；开始菜单入口保留。完成后启动软件，选择校招/社招/实习方向。
4. 在“我的简历”填写本人真实资料，多段教育/工作/项目经历各自添加；保存后切换页面并重开软件确认内容仍在。敏感信息和登录会话保存在本机。
5. “招聘项目”刷新岗位后按公司/城市/方向筛选，把适合的岗位加入购物车。无岗位/接口失败应显示真实状态；不要把样本岗位说成官网实测。
6. 从公司与邮箱页或简历同步入口登录本人招聘账号；检查官网资料和附件，必要时手动接管。扫码和验证码由本人完成；界面“打开/填写”不等于官网保存或成功投递。
7. 最终申请/投递必须检查岗位和官方回执，未观察到成功不能记为已投递。平台限制、验证码或 403 应停止并复核，不继续刷请求。
8. 连接 AI Agent 时通过“复制接入 Prompt”取得私有凭证；录像只拍遮罩的界面，不拍复制后的内容、真实简历、登录二维码或邮箱授权码。

## 升级、备份和恢复

- 在设置中先导出备份；更新时结束正在进行的官网工作区/批量任务。
- 只有实际注册安装的 Windows x64 版才允许直接安装更新；源码预览/解包便携版不能被当作已安装版。
- 更新检查必须是较新的正式版本、匹配架构的唯一安装包以及对应 SHA-256。下载校验后再确认安装；失败提示应保留，不能只凭进度 100% 推断升级成功。
- 安装助手就绪并确认交接后才退出旧软件；重开界面的版本、简历、附件、登录会话及 API 配置需复核。卸载默认保留本机用户资料。
- 当前真实 38→39 本机隔离验收已通过，两种桌面快捷方式偏好各8组验证；39默认路径首装/重装/卸载恢复6组通过。测试发布响应是受控样本，公众下载和真实招聘账号会话仍需单独验证。

## 录制顺序与证据

| 片段 | 展示动作 | 录制前门槛 |
|---|---|---|
| 下载安装 | 下载来源、hash、向导、首次启动 | 正式资产齐全且公网下载成功；本地候选只能注明候选演示 |
| 简历维护 | 空表→添加经历→保存→重开 | 演示资料清楚标记为样本，不能展示本人隐私 |
| 真实岗位 | 六家官网读取→筛选→官方岗位链接 | 当前版本实际结果，注明岗位随日期变动；不捏造可申请状态 |
| 平台资料同步 | 本人登录→字段/附件→官网保存→重开回读 | 各支持平台完成实际账号验收；不拍扫码凭证 |
| 合法申请 | 选岗→本人确认→官方回执→软件记录 | 明确授权具体申请；未知回执不能放进成功片段 |
| 反馈 | 问题分类/选填→脱敏日志→反馈回执 | 默认生产 HTTPS 服务和异机公网链接可用 |
| 更新 | 旧版→检查下载/hash→交接→新版保留资料 | 正式旧版和较新稳定包都可下载，真实版本和资料比对 |

维护者录制前以 [完整验收矩阵](development/mvp-acceptance.md) 逐项过门槛。可先演示本地简历与真实岗位读取，但这种片段不算完整目标达成，也不能宣传 bug 率低于 1%。

`node scripts/record-candidate-demo.cjs` 仅录真实可见Windows解包候选，使用独立样本用户目录，实际新建/重命名/保存/进程重开、匿名官网岗位刷新/筛选/本地购物车及遮罩Agent页。视频保存在忽略的 `.local-data/demo-<版本>-<随机>/`，报告与两个原始WebM保留；公开视频须标注候选/样本，且不能剪辑成已完成真实申请、反馈或正式更新的暗示。此脚本没有外部消息/申请动作。

## 反馈定位

记录软件版本、系统、操作步骤、期望与实际结果。优先使用软件“遇到问题反馈”入口，只分享已脱敏的诊断；生产服务未配置时应诚实提示未发送。反馈失败可保留待重试记录，不能冒充已送达。公开材料不附真实姓名/电话/身份证/完整简历/Token/网站 Cookie。
