# 简历字段缺口分析（2026-07-26 六大厂考古）

> 本文记录 2026-07-26 对腾讯、字节、小米、京东、美团、百度六家招聘站「真实简历编辑页字段」的考古结果，对照 App 现有字段找出缺口。目的是兑现 [agent.md](../../agent.md) 第 26 行的承诺：**「简历表单的字段需要涵盖所有大厂可能让用户填的所有字段」**。
>
> 字段考古由 6 个并行子代理执行。证据分两级：**实锤**（从招聘站 JS bundle 源码逐字提取）/ **推断**（基于官方 FAQ + 社区帖，字段标签未亲眼确认）。下文每条都标注证据等级。

## 证据强度总览

| 公司 | 字段证据来源 | 强度 |
|------|------------|------|
| 腾讯 | 社招 `Resume_zh-cn.js` + 校招 `V2Send_zh-cn.js` i18n bundle（源码级） | 🟢 实锤 |
| 京东 | 校招 `umi.js` bundle（源码级，含 label/name/placeholder/下拉选项）；社招 302 登录墙未实锤 | 🟢 校招实锤 / 🔴 社招待登录 |
| 字节 | 登录墙未突破，基于隐私指引 + 校招公告 + 社区帖推断 | 🟡 推断 |
| 小米 | 飞书 mioffice ATS，字段由企业后台配置，外部不可见；基于飞书标准 schema + 牛客推断 | 🟡 推断 |
| 百度 | SSR 未登录不渲染，基于搜索片段缓存 + 通用模板推断 | 🟡 推断 |
| 美团 | 登录墙未突破，基于官方 FAQ（分区级确认）+ 宣讲通知推断 | 🟡 推断（分区级实锤，字段级推断）|

> **共性结论**：校招字段远比社招丰富（腾讯校招 11 区 vs 社招 6 区；京东校招 10 区）。App 字段缺口主要集中在**校招**。

## 一、App 现状（对照基准）

App 简历字段分三层定义，存在**内部不一致**（这是第一类缺口，确定可修）：

| 层 | 文件 | 作用 |
|----|------|------|
| 数据层 | `electron/seed.cjs` | 定义所有字段的默认值（最全） |
| UI 层 | `src/index.html` + `src/app.js` REPEATABLE_TEMPLATES | 用户实际能填的字段（部分 seed 字段没渲染） |
| 映射层 | `electron/resume-plan.cjs` | 自动填表时的字段匹配规则（部分 seed 字段没规则） |

### 1.1 第一类缺口：UI 层漏渲染 seed 已有字段（用户填不到）

这些字段 seed 里有，但前端模板没渲染，等于用户**无法填写**：

| 字段 | 所属段 | seed 位置 | 说明 |
|------|--------|-----------|------|
| `isUnified`（统招） | education | `emptyEducation()` | 校招常见，京东/腾讯都要 |
| `researchDirection`（研究方向） | education | `emptyEducation()` | 硕博岗 |
| `thesisTitle`（毕业论文） | education | `emptyEducation()` | 校招 |
| `isOutsource`（是否外包） | experience | `emptyExperience()` | 社招背调核实项 |
| `reportTo`（汇报对象） | experience | `emptyExperience()` | 管理岗 |
| `teamSize`（团队规模） | experience | `emptyExperience()` | 管理岗 |
| `scale`（项目规模） | projects | `emptyProject()` | |
| `client`（客户） | projects | `emptyProject()` | toB 项目 |
| `height`（身高） | basic | `defaultBasic()` | 罕见，但 seed 有 |
| `avatarUrl`（证件照） | basic | `defaultBasic()` | 腾讯/京东/百度校招都要 |
| `previouslyEmployed`（曾被录用） | compliance | `defaultCompliance()` | 合规 |
| `criminalRecord`（无犯罪声明） | compliance | `defaultCompliance()` | 合规 |

### 1.2 第二类缺口：映射层漏规则（用户能填但自动填表不写入）

| 字段 | 说明 |
|------|------|
| `education.is211` | 双一流，腾讯/京东校招筛简历权重高 |
| `experience.isOutsource` | 外包标记 |
| `basic.avatarUrl` / `basic.height` | 罕见 |
| `intention.salaryUnit` | 薪资单位（月薪/年薪） |
| `intention.willingness.*` | 出差/外派/加班/夜班意愿 |
| `intention.preferredLocations` | 多城市排序（校招多志愿） |

## 二、各公司字段缺口（招聘站要、App 完全没有）

### 2.1 腾讯（🟢 实锤，校招缺口最大）

腾讯社招字段极简（6 区，无项目/技能/证书/语言/家庭/合规独立区），**校招才是字段主战场**（11 区）。校招 `V2Send_zh-cn.js` bundle 实锤字段中，App 缺失按重要性排序：

| 缺失字段 | 区 | 证据 | 重要性 | 说明 |
|---------|----|------|--------|------|
| **AI 应用技能**（整区） | AiSkill | 🟢 bundle 实锤 | ★★★ | 2026 新增：AI 协作任务描述 / 常用 AI 工具&模型（Cursor/Copilot/Claude等）/ 相关作品链接。校招差异化字段 |
| **语言能力结构化** | Language | 🟢 bundle 实锤 | ★★★ | 开发语言 / 英语等级(下拉)+分数 / 外语等级 / 其他英语等级 / 其他语言证书。英语等级是机筛加分项 |
| **GPA + GPA-BASE**（双字段） | Education | 🟢 bundle 实锤 | ★★★ | GPA 数值 + 满分绩点，且 GPA < BASE 校验。App 只有 rank 文本 |
| **成绩排名下拉**（gradeRanking） | Education | 🟢 bundle 实锤 | ★★ | 腾讯是分段下拉（前10%等），App 是自由文本 |
| **实习经历独立区** | Practice | 🟢 bundle 实锤 | ★★★ | 腾讯把实习和正式工作分开。App 混在 experience 无法区分 |
| **意向信息细分** | ApplyInfo | 🟢 bundle 实锤 | ★★ | 事业群(BG)/部门/面试城市/技术方向/是否接受其他城市分配/实习时长/每周出勤天数/科研意愿 |
| **院系/实验室/目前就读地** | Education | 🟢 bundle 实锤 | ★★ | education 只有 school/major，缺 department/laboratory/schoolLocation |
| **获奖信息结构化** | award | 🟢 bundle 实锤 | ★★ | 奖项名称+类型(下拉)+时间+说明，多段。App 是单文本 |
| **QQ号** | MainInfo | 🟢 bundle 实锤 | ★ | basic 无 qq |
| **紧急联系人** | MainInfo | 🟢 bundle 实锤 | ★★ | 姓名+电话（≠ family 亲属） |
| **资料证明人** | Certifier | 🟢 bundle 实锤 | ★★ | 姓名+身份+电话（建议填导师/辅导员，≠ family） |
| **作品三元组** | Production | 🟢 bundle 实锤 | ★★ | 名称+链接+密码/提取码，最多 5 组 + 三张精选作品图 |
| **游戏经历**（整区） | game | 🟢 bundle 实锤 | ☆ | 仅游戏岗：品类/时长/成就。非通用，可选 |

> ⚠️ **社招反向提醒**：App 的 `nativePlace/ethnicity/politicalStatus/maritalStatus/idCard/height/family[]/compliance` 在腾讯**社招页根本不要**，当前 `createTencentResumePlan` 会把它们都生成 plan 条目，到社招页全部判 manual，等于噪音。建议社招分支过滤。

### 2.2 京东（🟢 校招实锤，结构化缺口最大）

京东校招 `umi.js` bundle 实锤 10 区。App 最大差距在**多个本该结构化的区，App 只有文本字段**：

| 缺失字段 | 区 | 证据 | 重要性 | 说明 |
|---------|----|------|--------|------|
| **证件类型 + 证件号码**（拆分） | 基本信息 | 🟢 bundle 实锤 | ★★★ | 京东证件号是简历唯一标识，支持护照/港澳台。App 只有 idCard 单字段 |
| **国家/地区** | 基本信息 | 🟢 bundle 实锤 | ★★ | App 缺（nationality 语义偏民族） |
| **校园经历**（独立分区） | 校园经历 | 🟢 bundle 实锤 | ★★★ | 活动名称/担任职务/经历描述。App 混在 experience 无法区分 |
| **荣誉奖励结构化** | 荣誉奖励 | 🟢 bundle 实锤 | ★★★ | 奖项类型/级别/名称/获奖时间/获奖情况。App extras.awards 是单文本 |
| **论文/期刊结构化** | 论文期刊 | 🟢 bundle 实锤 | ★★ | 论文名称/作者顺序/发表时间/刊物机构/论文详情。App extras.publications 单文本 |
| **发明成果专利结构化** | 发明成果专利 | 🟢 bundle 实锤 | ★★ | 成果类型/名称/登记号/登记日期/发明人排名/核心简介。App extras.patents 单文本 |
| **学院名称**（college） | 教育经历 | 🟢 bundle 实锤 | ★★ | App 只有 school |
| **专业类别**（学科门类下拉） | 教育经历 | 🟢 bundle 实锤 | ★★ | 工学/经济学等，App 只有 major 文本 |
| **学习形式**（studyMode 枚举） | 教育经历 | 🟢 bundle 实锤 | ★★ | 统招全日制/非全日制/第二学位/交换/自考/其他。App 的 isFullTime+isUnified 两布尔无法表达后三种 |
| **是否最高学历 / 是否双学位** | 教育经历 | 🟢 bundle 实锤 | ★ | App 缺 |
| **实验室**（laboratory） | 教育经历 | 🟢 bundle 实锤 | ★ | 与腾讯一致，App 缺 |
| **专业成绩排名下拉** | 教育经历 | 🟢 bundle 实锤 | ★★ | 前5%/10%/20%/30%/40%/50%。App rank 是文本 |
| **开发语言**（独立下拉） | 语言证书技能 | 🟢 bundle 实锤 | ★★ | 京东把技能拆 6 子项，App 颗粒度不够 |
| **期待面试地点**（含海外/时区） | 投递 | 🟢 bundle 实锤 | ★ | App 缺 interviewLocation |
| **意向业务方向** | 投递 | 🟢 bundle 实锤 | ★ | 零售/物流/科技等 |
| **是否接受职位调剂** | 投递 | 🟢 bundle 实锤 | ★ | App intention 缺 |
| **实习生三件套** | 投递 | 🟢 bundle 实锤 | ★ | 最快到岗/可实习时长/每周出勤天数 |

### 2.3 字节（🟡 推断）

字节登录墙未突破，基于隐私指引 + 社区帖推断。App 相对字节的实质缺口很少（App 字段超前）：

| 缺失字段 | 重要性 | 说明 |
|---------|--------|------|
| **学校级别枚举**（schoolTier） | ★★★ | 985/211/双一流/海外。App 只有 is211 布尔，粒度不足。字节校招筛简历强相关 |
| **GPA** | ★★ | App education 无 GPA（与腾讯一致） |
| **专业排名**（区别于学位 rank） | ★ | 需区分「成绩排名」vs「学位等级」 |
| **实习经历独立段** | ★★ | 字节校招独有，App 混在 experience |

> 字节简历阶段**基本不采**籍贯/民族/政治面貌/婚姻/身高/家庭关系（onboarding 阶段才采），App 这些字段映射字节时跳过。

### 2.4 小米（🟡 推断，飞书 ATS）

小米用飞书招聘（与字节同源 mioffice），字段由企业后台配置，外部不可见。App 对小米实质缺口：

| 缺失字段 | 重要性 | 说明 |
|---------|--------|------|
| **附件简历文件**（resumeFile） | ★★★ | 小米校招社招都强烈依赖附件简历 PDF，App 完全没有此概念 |
| **工作年限**（workYears） | ★★ | 社招必填，App 无独立字段（需从 experience 推算） |

### 2.5 百度（🟡 推断）

百度走「少而精 + 附件简历兜底」路线，在线表单字段少：

| 缺失字段 | 重要性 | 说明 |
|---------|--------|------|
| **行业类别**（industry） | ★★ | 工作经历区，App experience 无 |
| **职位年薪**（每段经历的薪资） | ★★ | 工作经历区下拉 |
| **工作地点**（每段经历） | ★ | App experience 无 per-job location |
| **可面试方式** | ★ | 现场/视频/电话多选 |
| **项目类型**（projects.type） | ★★ | 科研/课程/实习/实践。百度把实习塞进项目 |
| **通用附件** | ★ | 区别于附件简历 |
| **GPA / 学业成绩** | ★★ | 与腾讯/字节一致 |

> 百度反向：App 的 skills/extras/family/compliance 富字段百度在线表单**全不要**，应通过生成 PDF 附件简历承载，而非填进在线表单。

### 2.6 美团（🟡 推断，分区级实锤）

美团官方 FAQ 确认分区：教育/实习/项目/校园经历 + 联系方式 + 志愿。

| 缺失字段 | 重要性 | 说明 |
|---------|--------|------|
| **校园经历结构化** | ★★★ | 美团校招独立分区，App 只有 extras.campus 单文本 |
| **志愿顺序锁** | ★★ | 美团第一/二/三志愿有序且提交后不可改，App roles 无序 |
| **意向部门/事业群** | ★★ | 到餐/到店/配送等，App 缺 |
| **证件类型拆分** | ★★ | 与京东一致，港澳台兼容 |
| **工作年限** | ★ | 与小米一致 |

## 四、本次落地的范围

鉴于缺口量大（校招结构化升级涉及 schema 变更），本次（极限模式）**先兑现确定性高、风险低的部分**：

1. **修第一类缺口**（UI 漏渲染 seed 字段）：补 12 个字段到前端模板 + HTML。零 schema 风险。
2. **补第二类缺口中的安全项**（不改 schema 的新字段）：`basic.qq`、`education.gpa/gpaBase/laboratory/department`、`intention.workYears/interviewCity/businessGroup/acceptAdjustment/acceptCityDeployment`、`skills.devLanguages/englishLevel/englishScore`、`extras.certifier`、`basic.emergencyContact/idType/idNumber`。这些是给现有对象加叶子字段，向后兼容。
   - **未做**：`education.rankPercentile`（排名下拉枚举）——当前 `rank` 已是文本字段可填「前10%」，单独的枚举字段留待结构化升级批次，避免与 rank 语义重叠。
3. **补映射规则**：把第一、二类缺口都加进 `resume-plan.cjs`，确保自动填表能写入。

### 不在本次范围（留给后续迭代）

- 结构化数组升级（awards/publications/patents/campusExperience/portfolio → 数组）：涉及 schema 变更和数据迁移，单独立项。
- 实习经历独立段（experience.category）：影响多段渲染逻辑，需单独设计。
- 附件简历文件（resumeFile）：涉及文件管理，单独设计。
- 腾讯社招字段过滤（createTencentResumePlan 按 recruitType 分流）：逻辑改动较大，单独做。

> 以上未做项已记录在本文档，不会丢失。

## 五、维护纪律

1. **证据分级**：本文每条缺口都标 🟢实锤 / 🟡推断 / 🔴待登录。补字段前确认证据等级，🟡推断的字段标「待登录验证」。
2. **登录补全**：字节/小米/百度/美团的字段标签需用真实账号登录后截图补全 🟡→🟢。这是当前最大盲区。
3. **改版联动**：招聘站改版后，本文 + `招聘官网汇总.md` + `resume-plan.cjs` 三处同步。
4. **采集日期**：2026-07-26。超过 30 天再次核对前不要当事实。
