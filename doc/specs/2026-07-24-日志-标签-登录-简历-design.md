## 子项目 A：内存日志系统（P0，无依赖）

### 目标
开发期调试用，内存环形缓冲近 50 条日志，零磁盘写入，避免臃肿。

### 架构
- 新建 `electron/logger.cjs`：单例，内部维护固定长度 50 的数组
- API：`logger.info(msg, meta?)` / `logger.warn(...)` / `logger.error(...)`
- 每条日志结构：`{ ts, level, msg, meta?, source }`，source 自动捕获调用方模块名
- 数组满 50 条时 `shift()` 挤掉最老的，**永不增长**
- **不写文件**——满足"避免重复写入写出"

### 集成点
- `electron/main.cjs`：`refreshJobs`、`openCompany`、`email:sync` 的 console.log/error 替换为 logger
- `electron/adapters/*.cjs`：`onProgress` 回调同时写 logger，抓取过程可追溯
- IPC `log:get`：返回最近 50 条
- 前端：设置页加"开发日志"折叠区，展示日志列表（时间/级别/消息），不自动刷新（手动点"刷新日志"）

### 不做
- 不做日志分级过滤 UI（50 条够少，全展示）
- 不做日志持久化（重启即清空，符合"内存"定位）

## 子项目 C：嵌入式登录系统（P2，架构级，基于 WebContentsView）

### 目标
软件内嵌 WebContentsView 加载招聘官网，用户登录，登录态保存在独立 profile，投递时复用。

### 架构
- 用 Electron 43 的 **WebContentsView**（BrowserView 已废弃），通过 `window.contentView.addChildView(view)` 嵌入现有 BrowserWindow
- 每家公司独立 user-data-dir：`<userData>/login-profiles/<companyId>`，cookie/localStorage 隔离持久化
- 主界面进入"登录模式"时：侧边栏保留可点击，主区域被 WebContentsView 覆盖（显示官网），顶部加地址栏 + "完成登录"按钮

### 数据流
1. 用户在"公司与邮箱"页点某公司的"登录"按钮
2. 主进程创建 WebContentsView，loadURL(公司 portal)，setBounds 覆盖主区域
3. 用户在嵌入浏览器里正常登录（输账号密码/扫码）
4. 登录态自动存入该公司的独立 profile（WebContentsView 用 persist:<companyId> session）
5. 用户点"完成登录"→ 移除 view，回到正常界面
6. 后续投递时复用该 session（已登录）

### 未登录检测（主动检测）
- 每家公司维护 `detectLogin(url)` 配置：打开投递/简历页后，用 `view.webContents.executeJavaScript` 检查特征
  - 腾讯：检查登录后才会出现的元素（如 `.tis-login` 消失或用户头像出现）
  - 百度：检查 `header-user` 等
- 检测到未登录 → 弹 toast "检测到未登录腾讯，是否现在登录？" → 点确认进入登录模式

### 关键约束
- WebContentsView 的 session 用 `session.fromPartition('persist:<companyId>')`，确保各公司隔离且重启后保留
- 嵌入浏览器禁用 nodeIntegration（安全），就是普通网页
- 不拦截用户的任何操作（用户在官网做什么由用户负责，软件只提供容器）

### 风险
- 各公司登录页结构不同，detectLogin 选择器需要逐家维护，可能改版失效（已在 browser-automation.md 记录此风险模式）
- WebContentsView 覆盖主区域时，需要正确处理 bounds（窗口 resize 时 view 跟随调整）
