# 多平台简历同步与职位聚合设计（2026-08-12）

## 初心对齐

用户只在「一键投递」维护一次简历，由软件逐个打开招聘官网，自动填写可安全识别的字段，并让用户在带退出栏的内嵌工作区核对。简历更新与岗位投递必须隔离：软件永不代替用户点击提交申请、投递职位或处理协议确认。

## 根因

旧版 UI 的「一键更新」没有调用已经存在的 Playwright 引擎：腾讯走基于全页关键词包含的旧脚本，其他平台只是打开网页。登录检查和真正填写还使用两套不同浏览器资料目录，导致预检结果不可信；任意未登录平台会阻断整批；腾讯进入核对态后又会被下一家公司覆盖。

## 统一流程

1. `resume-sync.cjs` 是 UI 和 Agent API 共用的唯一编排器。
2. 每次只处理一家；出现登录、自动填写后核对或手动接管即暂停，保留内嵌退出栏。
3. 登录失败继续时重试当前公司；核对/手动完成后继续下一家公司。
   “全部都要”会把每家公司展开成 `社招 + 校招` 两个独立同步目标，不再静默按社招处理。
4. 字段执行采用 `inspect → match → write → read-back verify`：
   - label/name/id/autocomplete 精确命中优先；
   - 低于 0.72 或最高候选接近时不写，转人工；
   - 文本先清空旧值，再触发 input/change/blur；
   - checkbox/radio 使用 `checked`；
   - 页面回读与期望严格一致才计入 verified；
   - 密码、验证码、提交、投递、申请、支付控件永久禁填。
5. 自动化不点击页面按钮；保存也留给用户核对后操作。校招页面的「提交简历」可能等同真实投递，必须展示风险提示。

## 平台分级

| 平台 | 简历 | 职位 | 说明 |
|---|---|---|---|
| 腾讯 | degraded / fill-and-review | verified | 自动写入只计延迟回读一致字段，保存仍由用户确认 |
| 字节 | degraded / path-confirmed | verified | 飞书招聘 ATS；官方独立简历编辑页，写入后必须人工核对 |
| 阿里 | degraded / path-confirmed | manual | 集团主管网是子站目录；未找到可验证公开职位源前不参与自动抓取 |
| BOSS | manual / permission-required | manual / permission-required | 用户协议禁止未经许可用第三方软件或爬虫自动访问 |

## 成熟方案复用

- JSON Resume（MIT）：作为后续标准交换层；现有中国招聘扩展字段继续保留。
- Playwright（Apache-2.0）：保留用于职位页面采集、桌面 UI 回归和适配器探索；产品内简历填写由 Electron `WebContentsView` 执行，保证登录与填写共用同一持久会话，不引入 LLM 自由点击。
- Folio（MIT）：借鉴 label/autocomplete 分级匹配、safe threshold、never submit；当前实现为本地重写，没有复制上游源文件。
- CareerPulse（MIT）：借鉴 adapter registry、confidence、needs-review、dynamic form；当前实现为本地重写。
- Crawlee（Apache-2.0）：借鉴职位采集的 adapter、限速、重试、去重边界，暂不新增重依赖。
- Reactive Resume（MIT）：只借分区编辑/导入导出架构，不整体内嵌。
- OpenResume / Automa（AGPL/商业许可）：不复制代码。

## 验收边界

代码可以验证编排、字段匹配、禁填、延迟回读、能力分级和 UI 退出栏。腾讯/字节/阿里要升级为 verified，仍需用户已有账号登录后完成一次真实的「填入→人工保存→重新打开回读」验收；未完成前保持 degraded，不得宣传成全自动闭环。

补充边界：本机保存的 PDF/DOC 附件当前不会自动上传到招聘官网；Agent 的 `/v1/resume` 默认返回脱敏简历，且不能直接启动官网填表、投递或邮箱读取。
