# 修复「一键投递跳腾讯404卡死」方案

## 核心结论
跳过选择，按最稳方向走：**继续用内嵌 WebContentsView（符合 agent.md「一体化 skill」初心），但彻底修好失败时不关 workspace 的致命 bug，并保证「取消/完成」控制条永远可见可点**。失败时自动关闭回到主界面 + Toast 提示原因，绝不让用户被困住。

## 改动清单（5 个文件）

### 1. `electron/login-manager.cjs` — 修 bounds + 控制条永远置顶
- **第 30 行**：`parentWindow.getSize()` → `parentWindow.getContentSize()`。修掉原生 view 偏高 ~28px、盖住顶部红绿黄交通灯的问题。
- **第 18-20 行常量**：删掉 `BOTTOM_BAR_HEIGHT`，新增 `TOP_BAR_HEIGHT = 52`。控制条从底部移到**顶部**——顶部位置稳定（紧贴标题栏），且不会被腾讯页内任何「返回首页」按钮干扰。
- **第 34-39 行 setBounds**：view 改为 `{x:0, y:TOP_BAR_HEIGHT, width:contentW, height:contentH - TOP_BAR_HEIGHT}`，给顶部控制条留位。
- **第 25 行 setParent**：补绑 `maximize`/`unmaximize`/`enter-full-screen`/`leave-full-screen` 事件，全部触发 `updateBounds()`。修掉全屏/最大化时 bounds 不刷新。
- **新增** `closeWorkspaceIfOpen()` helper：幂等关闭（view 不存在时直接 resolve），供 adapter 调用。

### 2. `electron/adapters/tencent-apply.cjs` — 失败必关 workspace（核心 bug）
- **第 67-74 行 `isNotFound` 分支**：return `failed` 前 `await workspace.closeWorkspaceIfOpen()`。
- **第 87-94 行 `login-required` 分支**：保留 workspace（设计上要让用户登录），但这是 intentional，**不改**。
- **第 100-106 / 110-115 行 `manual-required`**：保留 workspace（让用户手动接管），**不改**。
- **`resolveTencentJobUrl`（第 30-37 行）**：把 `http://` 强制规范化为 `https://`；fallback 时不再 throw，直接用 `job.url`（即使是 http 也规范化后用）。

### 3. `electron/main.cjs` — 调用方兜底关 workspace
- **`applyCart`（第 407-428 行）**：adapter 返回 `failed` 时 `await loginManager.closeWorkspace()`（保留 review-required/manual-required/login-required 的 workspace）。catch 分支（第 420-427 行）补 `await loginManager.closeWorkspace()`。
- **`applied:refresh-status`（第 705-735 行）**：adapter 抛错或返回 `failed` 时关 workspace。
- **`handleCommand` 的 `fill_resume`（第 106-114 行）**：包 try/catch，失败时关 workspace + finishTask。
- **`resume:fill-all` 最后一家 catch（第 685-689 行）**：catch 后关 workspace。

### 4. `src/styles.css` — 控制条从底部移到顶部
- **第 533 行 `.workspace-bar`**：`bottom:0` → `top:0`；`box-shadow` 从 `0 -6px 20px` 改成 `0 6px 20px`（阴影朝下）。height 维持 52px（配合新的 TOP_BAR_HEIGHT）。

### 5. `src/index.html` / `src/app.js` — 控制条文案与可见性保险
- workspace 激活时强制 `workspaceBar.classList.remove('hidden')`，并加一句注释说明为什么放顶部（避开原生 view + 腾讯页内导航干扰）。文案维持「取消 / 完成」。
- `renderWorkspaceStatus` 在收到 `active:false` 时确保 view 已关、控制条隐藏。

## 不改的地方（保持 intentional）
- `tencent-fill.cjs` 的 `review-required` / `login-required` 分支：留给用户登录和核对。
- `tencent-status.cjs` 的 `inspected`：留给用户看状态。
- `_manual-fill.cjs` / `_manual-apply.cjs` 的 `manual-required`：设计目的就是打开官网。

## 验证方式
- 手测：购物车里放一个已下线的腾讯岗位 → 点一键投递 → 应自动关 workspace + Toast「该岗位已下线」+ 回到购物车。
- 手测：正常岗位 → 点一键投递 → workspace 打开，**顶部**有「取消/完成」控制条可点；点「取消」立即回到主界面。
- 手测：窗口最大化/还原 → 控制条位置不错乱、腾讯页不盖控制条。
- 运行现有单元测试：`pnpm test`（应该 78/78 仍过，因为不动 adapter 数据契约）。
- 静态检查：`node --check` 所有改动文件。

## 为什么这样改最稳
- 不改架构（仍是内嵌），符合你「一体化 skill」初心，工作量可控。
- 失败自动关 + Toast 是你最不容忍的「被困住」的直接解药。
- 控制条移顶部：z-order 上原生 view 不覆盖顶部 52px，且顶部位置稳定不依赖底部布局推断，从根上消除「看不见按钮」的可能。
- `getContentSize()` 是 Electron 官方推荐的 WebContentsView bounds 计算方式，修掉一个潜伏 bug。
