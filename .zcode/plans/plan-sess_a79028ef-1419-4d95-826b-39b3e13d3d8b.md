## 校招/社招分流方案

### 核心事实（实测确认）
- **腾讯**：社招 API 加 `recruitType=2` 切校招（实测 2307 个校招岗）
- **百度**：URL 换 `campus-list`（与 social-list 同结构 SSR）
- **字节/小米**：飞书 ATS，`recruit_type.parent.name` 已能区分社招/校招
- **京东/美团**：需探测校招端点参数（实现时逐家确认）
- **实习细分**（暑期/日常/可转正）：各家 API 都没有此字段，只有"校招"大类。**选项设全但数据随站点能力**——能细分的细分，不能的归入"校招"，绝不造假

### 1. 数据结构
`settings.jobs.recruitType`：
- `'all'` 全部 / `'social'` 社招 / `'campus'` 校招
- 实习细分选项（暑期/日常/可转正）也列出，但标注"部分公司支持"

### 2. 首启弹窗（onboarding dialog）
- 用 `meta.onboardingSeen`（已存在但未使用）控制，首启时弹 dialog
- 选项卡片：社招 / 校招 / 暑期实习 / 日常实习 / 都看看
- 选完写入 `settings.jobs.recruitType`，置 `onboardingSeen = true`
- 复用现有 dialog 模式（如 #jobDialog），不新增 page

### 3. 设置页 recruitType 下拉
- 紧挨 #jobsDaysBack 加 `<select id="recruitType">`（全部/社招/校招/暑期实习/日常实习/可转正实习）
- 照抄 jobsDaysBack 的"扁平传入 + 嵌套存储"模式
- main.cjs settings:update handler 加 recruitType 转存

### 4. 适配器改造（6 家）
主链路：`refreshJobs` 读 `settings.jobs.recruitType`，传给 `adapter.fetch({ recruitType, ... })`

每家分两档：
- **腾讯**：`recruitType !== 'social'` 时 URL 加 `&recruitType=2`（校招）；normalizeJob 的 jobType/tags 改成 `'校招'`
- **百度**：`recruitType !== 'social'` 时 BASE 换成 `campus-list`；jobType 改 `'校招'`
- **字节/小米**：按 `recruit_type.parent.name` 过滤（选 social 只留社招，选 campus 只留校招）
- **京东/美团**：探测校招端点参数后切换；探测不通则 campus 模式返回空 + 提示"该校招源待适配"

### 5. 前端卡片
- normalizeJob 的 jobType 字段已有，前端 tag 渲染已支持"校招"（橙色 tag-intern）
- 实习细分 tag：前端 internTypes 白名单已有（暑期实习/日常实习/可转正实习），数据有就显示

### 6. 迁移
store.cjs migrate() 补全老用户的 `settings.jobs.recruitType = 'all'`

### 执行顺序
1. settings 数据结构 + 迁移 + 设置页下拉
2. 首启 onboarding dialog
3. 腾讯校招适配（recruitType=2，最确定）
4. 百度校招适配（campus-list URL）
5. 字节/小米过滤适配
6. 京东/美团探测 + 适配
7. 实测校招抓取 + 截图验证 + 提交

### 不做
- 不伪造实习细分（API 没有就不标）
- 不做校招投递（投递要登录态，下一阶段）
- 不改 normalizeJob 的已有字段语义
