## 第二部分：腾讯适配器（真实抓取）

### 1. 新建 `electron/adapters/` 目录 + 腾讯适配器
新建 `electron/adapters/tencent.cjs`，实现：
```
listTencentJobs({ daysBack = 30, pageSize = 50 })
  → 调 https://careers.tencent.com/tencentcareer/api/post/Query
  → 参数: timestamp/pageIndex/pageSize/language=zh-cn/area=cn
  → 翻页直到 LastUpdateTime 早于 (今天 - daysBack)
  → 每条 Post 归一化成统一岗位结构
  → 带 User-Agent + Referer，请求间 sleep 控频（~300ms）
  → 容错：单页失败跳过、500/空跳过、总数上限保护（防失控）
```

**字段映射**（API → 统一结构）：
| API 字段 | 统一字段 |
|---|---|
| PostId | id（加前缀 `tencent-`） |
| RecruitPostName | title |
| BGName | department |
| LocationName | city |
| CategoryName | tags[0] |
| RequireWorkYearsName | experience |
| Responsibility | summary |
| LastUpdateTime（"2026年07月23日"） | postedAt（转 ISO `2026-07-23`） |
| PostURL | url |
| — | companyId: 'tencent', type: '全职', education: '待进详情', salary: '薪资面议', source: '腾讯招聘官网', match: 0（匹配度留空，后续 AI 评分阶段再算） |

### 2. 适配器契约文档化
更新 `doc/integrations/browser-automation.md` 或 `大厂清单.md`，登记腾讯适配器：API endpoint、字段映射、最后实测日期、已知坑（BGName 非 DepartmentName、学历要进详情）。

### 3. `electron/main.cjs` refreshJobs 接入
- 改造成真正调用腾讯适配器
- 读 `settings.jobs.daysBack`（默认 30）
- 抓取结果**合并**进 `state.jobs`（按 id 去重，已收藏的岗位保留 favorite 状态）
- task 记录抓取进度和结果：「已抓取腾讯 N 个岗位（近 30 天）」
- **降级**：腾讯 API 异常时 task 标 error，不清空已有数据，返回友好错误

### 4. 设置项 `settings.jobs.daysBack`
- `seed.cjs` 的 settings 加 `jobs: { daysBack: 30 }`
- 设置页 `src/index.html` 加一个数字输入「岗位抓取范围（天）」

腾讯 API 用 `electron/main.cjs` 里已有的 `net.request`（Electron 内置，已在第 147 行用于 GitHub 更新检查），不引入新依赖。封装一个轻量 `fetchJson(url)` 给适配器用。

## 不做的事（诚实边界）

- ❌ 不做其他大厂（跑通腾讯一家再复制）
- ❌ 不做简历自动填写（同理，下一阶段）
- ❌ 不动校招（join.qq.com 是另一套 API，单独适配）

## 一个要你知晓的事实
腾讯岗位列表 API 不需要登录——这跟你"用户本机+登录态自用"的原则不冲突：抓岗位本来就不涉及你的身份，只有投递才需要登录态。其他大厂（阿里/字节等）是否也有公开 API，要逐家调研后才能定。
